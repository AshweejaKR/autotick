PROJECT SUMMARY
================================================================================

AutoTick is a modular, broker-independent framework supporting Live, Paper,
Backtest, and Replay modes through one codebase.

Core rules:

- Strategies generate signals and do not select modes or brokers.
- ProviderFactory selects market data, account, execution, and session timing.
- Broker SDK code stays inside broker adapters.
- Models and provider contracts stay normalized.
- CalendarSessionManager owns the single-exchange schedule, timezone, session time, and market-hours checks.
- RiskManager owns sizing and risk limits.
- TradeManager owns order and position workflow.
- Optional production components are added only in their planned phase.

PROVIDER CONTRACTS
================================================================================

Aligned constructors:

- Session(credentials_file=None)
- Account(session, configured_capital=0.0)
- Execution(session)
- MarketData(session, exchange="NSE")

MarketDataProvider:

- connect(), disconnect()
- subscribe(), unsubscribe()
- get_tick(): latest LTP, current volume, and timestamp
- get_bars(): normalized OHLCV bars
- get_bars() start_date and end_date are optional
- default end: current provider time
- default start: 5 days earlier, or 30 days for daily bars

AccountProvider:

- connect(), disconnect()
- get_balance(), get_margin(), get_buying_power(), get_profile()
- AngelOne and simulated providers return the same Account model

ExecutionProvider:

- place_order(), modify_order(), cancel_order(), cancel_all()
- get_order(), get_order_status(), get_orders()
- get_positions(), get_holdings(), get_trades(), get_pnl()
- square_off()

Simulation-only input helpers:

- SimulatedMarketDataProvider.set_tick()
- SimulatedMarketDataProvider.set_bars()
- SimulatedState keeps shared account, tick, bar, subscription, and UI state

MODE MAPPING
================================================================================

Mode                 Market Data          Account       Execution     Timing
-------------------  -------------------  ------------  ------------  ------------
Live                 Selected broker      Broker        Broker        Realtime
Paper, UI disabled   Selected broker      Simulated     Simulated     Realtime
Paper, UI enabled    UI shared simulation Simulated     Simulated     Realtime
Backtest             HistoricalProvider   Simulated     Simulated     Fast
Replay               HistoricalProvider   Simulated     Simulated     Replay speed

Paper behavior:

- UI disabled: ProviderFactory creates selected-broker market data.
- UI enabled: control panel and runner share SimulatedSession/SimulatedState.
- broker_auto_fetch false: UI-only manual data.
- broker_auto_fetch true: selected real broker supplies initial UI data.
- broker_auto_fetch has no effect when UI is disabled.
- Paper MARKET orders fill at the current active market-data LTP.
- Filled simulated BUY orders subtract cost from balance, margin, and buying power.
- Filled simulated SELL orders add proceeds and record realized P&L.
- Simulated BUY orders are rejected when available funds cannot cover the cost.
- Paper never sends an order to the broker.

CONFIGURATION BEHAVIOR
================================================================================

config/default.yaml is the only default YAML.

Relative credentials, CSV paths, and persistence paths resolve from the YAML
file directory before validation.

production secrets:
- AngelOne secrets remain in the configured angelone_keys.env file.
- required values are API_KEY, CLIENT_ID, PASSWORD, and TOTP_SECRET.
- the secrets path must exist, be a regular file, and be readable.
- blank lines and # comments are ignored.
- duplicate keys, missing required keys, and blank required values fail startup.
- secret errors identify keys only and never expose secret values or file contents.
- one shared parser is used by config validation and AngelOneSession.
- Paper validates AngelOne secrets only when broker-backed market data or
  broker_auto_fetch needs AngelOne access.
- fully simulated Paper, Backtest, and Replay do not require AngelOne secrets.
- angelone_keys.env is explicitly ignored by Git.

LIVE production safety:
- mode live requires persistence.enabled true.
- mode live requires reconnect.enabled true.
- mode live requires session.only_market_hours true.
- mode live requires logging.enabled true.

persistence:
- enabled false keeps the previous in-memory behavior outside Live mode.
- enabled true requires a .db state_path.
- one SQLite database stores isolated profiles keyed by mode, broker, exchange,
  strategy, and sorted symbols.
- Live and Paper recover before subscription and strategy setup.
- Backtest and Replay start fresh and save final state for reporting.

reconnect:
- enabled true applies only to Live and broker-backed Paper runs.
- temporary network and broker-service failures retry indefinitely.
- retry delay doubles from initial_delay_s up to max_delay_s.
- authentication recovery is limited by auth_max_attempts.
- token refresh runs before full TOTP login.
- strategy processing stays paused until subscriptions and state reconcile.
- broker writes remain once-only; uncertain writes reconcile, activate the kill
  switch, and stop safely without automatic resubmission.

simulated.ui_data_enabled:
- false: normal ProviderFactory Paper bundle.
- true: Windows control panel plus Paper runner in one process.
- supported only in Paper mode.

simulated.broker_auto_fetch:
- requires ui_data_enabled true.
- false keeps UI data manual.
- true requires a real selected broker.

market and session scope:
- one run uses one market, one exchange, and one CalendarSessionManager profile.
- all configured symbols must follow that exchange calendar.

session.schedule_type:
- DAILY: trading_days, market_start, market_end, and square_off_time are required.
- WEEKLY: week_start_day/time and week_end_day/time are required; a paired
  daily_break_start/end is optional.
- ALWAYS_OPEN: no opening or closing fields; every day remains open.
- timezone is required as an IANA timezone.
- closed_dates optionally closes specific dates for DAILY and WEEKLY.

session.only_market_hours:
- true: Live and Paper check the calendar before provider login, subscription,
  or strategy setup. A closed market logs WARNING with next_open and stops.
- false: the realtime runner ignores the schedule gate and keeps processing.
- account balance does not gate strategy tick processing; zero balance produces
  zero risk quantity and blocks order submission.

engine.loop_sleep_s:
- minimum realtime loop delay.
- broker throttling and API response time can make a cycle longer.

trade.position_type:
- POSITIONAL is the default.
- TradeManager square-off targets INTRADAY positions only.
- current main.py does not yet invoke automatic square-off.

RUNTIME FLOW
================================================================================

Current CLI startup:

main.py
  -> load YAML and resolve relative file paths
  -> validate configuration and required broker secrets
  -> enforce LIVE production safety flags
  -> configure logging
  -> select UI flow or ProviderFactory
  -> create the single-exchange calendar profile
  -> create RiskManager, TradeManager, RecoveryManager, and optional ReconnectManager
  -> for Live/Paper with the gate enabled, stop before provider setup when closed
  -> connect providers
  -> restore SQLite state and reconcile known provider records
  -> subscribe configured symbols
  -> initialize strategies after the open-market check
  -> run realtime or historical loop
  -> save changed state before provider shutdown
  -> unsubscribe and disconnect providers

Live and broker-backed Paper startup failures enter the same reconnect path
before strategy setup. Fully simulated Paper, Backtest, and Replay do not.

Current realtime loop:

CalendarSessionManager.now()
  -> market-hours decision
  -> account balance updates RiskManager capital
  -> broker/UI get_tick()
  -> pending-order reconciliation
  -> stop-loss, target, and trailing-stop monitoring
  -> SimpleStrategy.on_tick() when no entry exists
  -> SignalValidator
  -> RiskManager sizing and validation
  -> TradeManager order state
  -> simulated or broker execution
  -> save the SQLite snapshot only when state changed
  -> wait engine.loop_sleep_s

On a recoverable broker failure, the realtime loop pauses, refreshes or logs in,
restores configured subscriptions, reconciles Phase 25 state, persists the
result, rebuilds strategies, and resumes. Authentication exhaustion and
uncertain writes activate safe shutdown.

Current historical loop:

HistoricalProvider timestamps
  -> update simulated clock and market-data time
  -> detect new trading day
  -> reset daily risk state and strategies
  -> process symbols through the same signal/risk/order flow
  -> save final state for reporting without resuming the historical cursor

TradingEngine and EventDispatcher are implemented core components. The current
CLI runner uses a direct provider/risk/trade loop and does not yet route main.py
through TradingEngine/EventDispatcher.

STRATEGY AND SIGNAL RULES
================================================================================

SimpleStrategy:

- on_initial_setup() loads the latest completed daily bar.
- previous close comes from that bar.
- BUY when LTP > previous_close * 1.005.
- no signal otherwise.
- one entered-symbol set prevents another entry for that symbol in the same
  active trading day.

SignalValidator:

- requires symbol and exchange.
- requires SignalType.
- quantity may be None; supplied quantity must be positive.
- price may be None; supplied price must be positive.
- does not size, manage risk, or decide exits.

RISK AND TRADE MANAGEMENT
================================================================================

RiskManager implemented behavior:

- configured quantity is capped by capital, risk percentage, price, and
  stop-loss distance.
- filled ENTRY orders increment trade_count.
- max_trades_per_day activates the kill switch.
- stop_loss(), target(), and trailing_stop() calculate price levels.
- trailing_sl_pct greater than zero activates trailing protection at target.
- trailing_sl_pct zero closes directly at target.
- check_daily_limits() can activate the max-loss kill switch.
- reset_daily_state() clears daily count and kill switch.
- daily trade count and kill-switch state can be exported and restored.

TradeManager implemented behavior:

- validates order-state transitions.
- tracks normalized orders.
- reconciles broker orders and positions.
- exports and restores normalized orders, positions, trades, and exit levels.
- startup reconciliation updates only known AutoTick broker records.
- unknown broker orders and holdings remain unmanaged and block duplicate entries.
- tracks position state, exposure, realized P&L, and unrealized P&L.
- provides intraday square-off orders.
- opens tracked positions only after filled entry orders.
- monitors fixed stop-loss first, then target-activated trailing protection.
- submits normalized exit orders and closes positions after filled exits.
- records normalized simulated trades and updates simulated cash and realized P&L.
- logs rounded execution prices, cost/proceeds, exit levels, P&L, and funds.

Current CLI runner does not yet:

- feed daily P&L into check_daily_limits().
- call automatic square-off.
- generate reports.

ORDER STATE MACHINE
================================================================================

NEW -> VALIDATED -> SUBMITTED
SUBMITTED -> OPEN / PARTIAL / FILLED / REJECTED / CANCELLED / EXPIRED
OPEN -> PARTIAL / FILLED / CANCELLED / EXPIRED
PARTIAL -> FILLED / CANCELLED / EXPIRED

Only a FILLED ENTRY consumes the daily trade limit.

POSITION STATE MACHINE
================================================================================

NO_POSITION -> ENTRY_PENDING -> OPEN -> EXIT_PENDING -> CLOSED

TradeManager owns position state. Provider adapters only normalize external
position and trade data.

LOGGING
================================================================================

Console levels and colors:

- ERROR: red
- WARNING: yellow
- INFO: white
- DONE: green

logger.done() is for successful completions such as login, logout, token
refresh, configuration load, order placement, and shutdown.

Rotating file logs remain plain and contain no ANSI color codes.

DESIGN PRINCIPLES
================================================================================

1. Correctness before speed.
2. Simplicity before complexity.
3. Maintainability before cleverness.
4. One normalized contract per provider capability.
5. Broker SDKs remain inside broker adapters.
6. Strategy remains focused on market conditions and signals.
7. RiskManager and TradeManager own risk and trade workflow.
8. One CalendarSessionManager owns the run's single-exchange schedule and time.
9. Add optional components only in their planned phase.
10. Keep README.md, PLAN.md, and this guide synchronized.
