PROJECT SUMMARY
================================================================================

AutoTick is a modular, broker-independent framework supporting Live, Paper,
Backtest, and Replay modes through one codebase.

Core rules:
- Strategies generate signals and do not select modes or brokers.
- ProviderFactory selects market data, account, execution, and session timing.
- Broker SDK code stays inside broker adapters.
- Models and provider contracts stay normalized.
- CalendarSessionManager owns the run's single-exchange calendar.
- RiskManager owns sizing and risk limits.
- TradeManager owns order, position, completed-trade, and report flow.
- Normal CLI SIGNAL validation routes through TradingEngine + EventDispatcher.
- Recovery/reconnect stays in the main runtime loop to preserve existing safe-recovery flow.

MODE MAPPING
================================================================================

Mode       Market Data          Account       Execution     Timing
---------  -------------------  ------------  ------------  ------------
Live       Selected broker      Broker        Broker        Realtime
Paper      Selected broker      Simulated     Simulated     Realtime
Backtest   HistoricalProvider   Simulated     Simulated     Fast
Replay     HistoricalProvider   Simulated     Simulated     Replay speed

Paper orders never reach broker execution. Simulated execution supports LONG and SHORT positions.
Backtest and Replay use only historical and simulated providers, so broker credentials
are not required.

CONFIGURATION
================================================================================

- autotick/config/default.yaml is the packaged default YAML.
- default.yaml is Live MCX GoldPetal; update GOLDPETAL30SEP26FUT after expiry.
- relative credential, CSV, persistence, report, and log paths resolve from the
  YAML file directory.
- AngelOne secrets stay in ignored angelone_keys.env.
- required AngelOne values: API_KEY, CLIENT_ID, PASSWORD, TOTP_SECRET.
- Live requires persistence, reconnect, only_market_hours, and logging enabled.
- one run uses one market/exchange calendar.
- old simulated control-panel flags are not part of current configuration.

SWING STRATEGY
================================================================================

- strategy_config.csv_file points to symbol,trigger_price watchlist data.
- max_position_value limits capital allocated per trade, including margin-aware sizing.
- RiskManager applies risk_per_trade_pct and stop-loss sizing.
- watchlist reloads once at each trading-day open.
- CSV removal blocks new entries but does not stop management of an open position.
- closed swing positions are removed from runtime subscriptions.
- recovery uses stable CSV_WATCHLIST profile identity.

MCX GOLDPETAL ORB STRATEGY
================================================================================

- LONG when LTP is above previous-day high + 0.15%.
- SHORT when LTP is below previous-day low - 0.15%.
- default.yaml uses one configured unit, 20% risk per trade, and 2% stop-loss.

RISK AND TRADE MANAGEMENT
================================================================================

RiskManager:
- owns position sizing and entry risk checks.
- applies max_position_value when configured, including broker-margin sizing.
- Live AngelOne entries use broker-calculated margin and charges before placement.
- calculates long/short stop-loss, target, and ATR trailing levels.
- records realized daily P&L and activates the kill switch at max loss or max trades.
- keeps the kill switch active after a runtime persistence failure.

TradeManager:
- owns normalized order-state transitions.
- tracks orders, positions, trades, and exit levels.
- reconciles known broker records.
- monitors stop-loss, target, and trailing-stop exits.
- supports signed short positions and BUY exits.
- closes positions only after filled exits.
- calculates realized P&L and triggers completed-trade reporting.
- automatically submits intraday exits at the configured square-off time.

SimulatedExecutionProvider:
- BUY opens/adds LONG or covers an existing SHORT.
- SELL closes LONG or opens SHORT for ENTRY intent.
- realized P&L and simulated funds update on LONG and SHORT exits.
- simulated.margin_pct reserves simple margin for futures Paper entries.
- square_off() closes both position directions.

ORDER STATE MACHINE
================================================================================

NEW -> VALIDATED -> SUBMITTED
SUBMITTED -> OPEN / PARTIAL / FILLED / REJECTED / CANCELLED / EXPIRED
OPEN -> PARTIAL / FILLED / CANCELLED / EXPIRED
PARTIAL -> FILLED / CANCELLED / EXPIRED

The first execution of an ENTRY order, partial or full, consumes the daily trade limit.

PERSISTENCE AND RECOVERY
================================================================================

- SQLite stores normalized runtime state.
- profiles are isolated by mode, broker, account identity, exchange, strategy,
  and symbols; swing uses stable CSV_WATCHLIST identity.
- Live and Paper recover state before strategy setup.
- Paper restores simulated account/trade state.
- unknown broker state remains unmanaged and duplicate entries are blocked.
- unresolved broker writes trigger reconciliation and safe shutdown.

RECONNECT
================================================================================

- Live and broker-backed Paper use ReconnectManager when enabled.
- temporary read/network failures use capped exponential backoff.
- authentication recovery attempts refresh before full login.
- subscriptions restore before reconciliation and strategy resume.
- broker writes are not automatically retried.

REPORTING AND AUDIT
================================================================================

- reports.enabled writes completed-trade CSVs, summaries, and audit records.
- reports.user_id is optional; broker client ID may be used when blank.
- completed ENTRY + EXIT pairs produce report trades.
- duplicate completed exits are skipped.
- strategy and combined summaries are recalculated from accumulated reports.
- reporting errors are logged and do not undo completed trades.
- audit records order transitions and recovery/reconciliation events.
- credentials and secret values are never written to audit output.

ENGINE AND EVENT FLOW
================================================================================

- EventDispatcher remains the normalized event router.
- TradingEngine exposes immediate normalized event dispatch and its queue event loop.
- normal CLI uses TradingEngine/EventDispatcher for SIGNAL validation.
- SignalValidator remains the validation handler for SIGNAL events.
- provider startup, persistence recovery, reconnect, and shutdown remain in the
  current main runtime loop because they include production-specific recovery behavior.

RUNTIME SAFETY
================================================================================

- Realized daily P&L feeds max-loss enforcement after each exit fill.
- Intraday positions are squared off at session.square_off_time; new intraday entries are blocked after that time.
- A runtime persistence-write failure blocks entries until restart, even across a daily reset.
- Historical fills retain their market timestamp and refresh account balance before each sizing decision.
- Closed Swing positions are unsubscribed and removed after order reconciliation.
- Simulated exits settle full losses even when the simulated balance becomes negative; risk sizing clamps capital at zero.

DESIGN PRINCIPLES
================================================================================

1. Correctness before speed.
2. Simplicity before complexity.
3. Maintainability before cleverness.
4. One normalized contract per provider capability.
5. Broker SDKs remain inside broker adapters.
6. Strategies focus on market conditions and signals.
7. RiskManager and TradeManager own risk and trade workflow.
8. One CalendarSessionManager owns the run's single-exchange schedule.
9. Keep README.md, PLAN.md, this guide, and runbook synchronized.
